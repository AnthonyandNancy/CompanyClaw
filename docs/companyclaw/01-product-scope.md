# 01 — 产品范围

依据：《CompanyClaw — MicroClaw Fork 完整实施书 V1.0》+ 产品负责人《需求冲突裁决与实施授权》+ Requirement V1.1。

## 1. 目标用户操作流

### 首次使用

1. 员工运行公司发放的安装包（如需 IT 首次批准，必须明确提示）。
2. 启动应用；系统自检执行组件状态。
3. 员工只输入自己的模型配置（提供商 / Base URL / Model ID / API Key），可连接测试与切换。
4. 员工在「微信连接」扫码绑定本人微信。
5. 员工本人手动登录公司 Web / 桌面业务系统并完成 MFA；应用只复用获授权的工作会话。
6. 本地可聊天；也可远程通过微信操作本人电脑。

### 远程使用

- 微信：「打开物业工程中心 → 工单 → 工单设置，搜索 ABC 公司，编辑结果列表的第一条，将负责人从李四改成张三」。
- Agent 定位、核对唯一标识、读取旧值、生成变更摘要。
- 微信展示「系统 / 公司 / 记录编号 / 字段 / 原值 / 新值 / 风险等级」。
- 员工确认后执行；保存后重新读取验证。
- 只有回读匹配才回复「已验证完成」。

## 2. 产品边界

**必须做**（实施书 §1.2）

- Windows 10/11 可安装应用（以 Windows 11 为主要验收平台）
- 个人模型配置
- 每机独立实例
- 微信扫码
- 浏览器与原生桌面操作
- Web / 桌面混合任务
- 微信审批
- 文件收发
- 权限防护
- 任务管理
- 可靠打包

**默认不做**（实施书 §1.2 + 裁决补充）

- 全员共用微信机器人并集中路由到不同电脑
- 云端集中管理平台
- 关机后远程唤醒执行
- 绕过锁屏 / UAC / MFA / 验证码
- 跨员工控制他人会话
- 对所有第三方软件承诺 100% 自主成功
- 无人**审批**（产品要求支持无人**值守**，不要求业务写入无需确认）
- 非官方个人微信 Hook（wxauto / wcferry 等）
- 同时维护两套差异很大的升级链路
- 员工自行解除 R3 限制

## 3. 必须向用户明确展示的限制

- 电脑离线、睡眠、锁屏、未登录、桌面会话不可用时，某些任务不可执行。
- 浏览器后台操作能力与交互式桌面能力不同。
- 无法可靠识别写入边界的操作，只能只读或需本机监督，不做远程自动写入。
- 微信发送状态与终端送达状态是两件事；无回执时不得宣称已送达。

## 4. 非功能要求（实施书 §1.3）

- 一人一机默认一套：Gateway / 微信身份 / 模型密钥 / 浏览器工作 Profile / 日志空间；按 Windows 用户 SID 隔离。
- 任务运行中可暂停 / 取消 / 紧急停止；同一交互桌面仅一个独占自动化任务占用键鼠。
- 本地配置与凭证随用户隔离；卸载默认保留用户数据并提供显式清除选项。
- 关键业务变更可追踪；不采集不必要的全文网页内容或模型思考过程。
- 支持升级回滚；重要设置与个人数据不因版本升级丢失。
- 普通员工日常使用不依赖管理员权限；默认不新增 Defender 排除项。

## 5. 发布分级

| 版本 | 门槛 |
|---|---|
| 技术预览版 | 仅在隔离测试环境验证模型、微信、Browser、Windows-MCP、文件处理；**不用于真实生产业务修改** |
| 内部试点版 | E01–E04、E06、E09、E11、E16、E17、E19 全部真实 PASS 后，进入与测试覆盖能力相符、且具备可靠事务边界的系统试点 |
| 正式交付版 | P0–P11 与所有适用 E01–E20 完成，处理全部阻塞 |

**双基线**：基线 A（原生能力兼容）与基线 B（远程操作安全）分别验收、不得混淆。
